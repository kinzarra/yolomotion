# Reel engine API

`packages/video/src/reel/` — everything a voiceover reel shares. Import from
`"../../reel"`.

## Anatomy of a template

```
src/templates/<id>/
├── index.ts        defineTemplate — id, name, schema, defaultProps, DURATION
├── schema.ts       zod contract: what a caller may change (brand text, CTA)
├── palette.ts      this reel's colors: Palette + a local *Colors object
├── timeline.ts     VO_RATE, SCENES, VOICEOVER, DURATION — the timing model
├── durations.ts    GENERATED by gen-voiceover.mjs — measured mp3 lengths
├── <Pascal>.tsx    the composition: <Reel> + one <Scene> per beat
├── ui.tsx          visual primitives shared across this reel's scenes
└── scenes/         one component per beat
```

Plus, outside the template folder:

```
scripts/scenarios/<id>.md        the brief this reel was built from
scripts/voiceover/<id>.json      TTS manifest: voice id, settings, spoken lines
public/voiceover/<id>/*.mp3      synthesised clips, normalised to -16 LUFS
```

## `<Reel>`

The shell: background, voiceover track, scenes, captions, then grade → grain →
vignette. A template renders nothing from the layer stack itself.

```tsx
<Reel
  palette={ovPalette}
  voiceoverDir="audience-overlap"   // public/voiceover/<dir>/
  voiceover={VOICEOVER}
  voRate={VO_RATE}
  captions={{ ... } | false}
  gradeOpacity={0.1}                // default 0.1
  bgMesh                            // drifting mesh under the scenes
  voVolume={1.4}                    // only for pre-loudness-pass clips
>
  <Scene spec={SCENES.hook} name="01 hook"><HookScene /></Scene>
</Reel>
```

`bgMesh` is for reels whose scenes do not paint their own full-frame
backdrop (`database-guide`). `voVolume` exists only for clips recorded before
`gen-voiceover.mjs` had a loudness pass; new reels leave it at the default 1.

The props are a discriminated union on `captions`. With captions on, the
voiceover lines must be full `VoLine`s (caption pages + measured duration).
With `captions={false}` — a reel whose scenes carry their own type — plain
`{ file, start }` entries are enough, so nothing has to invent empty pages.

## `<Scene spec={SceneSpec} name={string}>`

A `<Sequence>` that takes seconds instead of frames. Rounding to frames
happens in one place, so neighbouring scenes cannot end up a frame apart.

## `buildScenes(lengths, startAt?)`

Lengths in order → `{ [beat]: { from, len } }` with accumulated starts.
Retiming one beat shifts every later beat automatically. `scenesDuration()`
returns the end of the last beat — that is what `index.ts` exports as the
composition duration.

## `defineVoiceover(DURATIONS, lines)`

Attaches each clip's measured duration to the authored line. A clip that has
not been synthesised yet falls back to a word-count estimate and logs a
warning — it must not throw, because the registry imports every template and
one unfinished reel would otherwise break Studio and every render.

`voiceoverEnd(lines, rate)` gives the moment the spoken track actually ends,
if a reel wants its duration set from the voice rather than from the beats.

## Captions

`<Captions>` is rendered by `<Reel>`; the `captions` prop configures it.

```ts
type CaptionStyle = {
  activeColor?: string | ((seconds: number) => string); // function = act change
  heroColor?: string;   // "+WORD"
  badColor?: string;    // "!WORD"
  top?: number;         // default 1408
  sideMargin?: number;  // default 90
  maxWidth?: number;    // default 880
  fontSize?: number;    // default 54
};
```

Word timing is derived, never authored: each word gets a weight from its
letter count plus a pause bonus for `,` `—` `.` `?` `!` `...`, and the clip's
measured window is split by those weights. Re-recording a line retimes its
words automatically.

`activeColor` as a function receives the current time in seconds — that is how
`audience-overlap` flips its highlight from red to green when the fix lands:

```ts
activeColor: (now) => (now < SCENES.yoloco.from ? ovColors.bad : ovPalette.primary)
```

## Server-side parameterization (props-driven timeline)

`yoloco-audience-fit` is the reference. For a template a render worker should
be able to re-voice without a commit, the timeline is a pure function instead
of module-level constants:

```ts
// timeline.ts
export const makeTimeline = ({ durations, beats }: TimelineOverrides = {}) => {
  const SCENES = buildScenes({ ...BEATS, ...beats });
  const VOICEOVER = defineVoiceover({ ...DURATIONS, ...durations }, LINES.map(
    ({ file, scene, lead }) => ({ file, start: SCENES[scene].from + lead })));
  return { SCENES, VOICEOVER, DURATION: scenesDuration(SCENES) };
};
export const { SCENES, VOICEOVER, DURATION } = makeTimeline(); // the default
```

The pieces, and why each is shaped that way:

- **Voiceover starts are `scene + lead`, never absolute seconds** — an
  overridden beat then carries its line with it. Absolute starts silently keep
  speaking over the previous scene's extension.
- **Schema** gains `durations` / `beats` / `voiceoverDir`, all optional; with
  none of them the render is bit-identical to the checked-in reel, so Studio
  and the CLI change nothing.
- **`durationInSeconds: (props) => makeTimeline(props).DURATION`** in
  `defineTemplate` — Root.tsx wires the function form into
  `calculateMetadata`, which both Studio and `selectComposition` execute, so
  the renderer needs no changes and a job never states the video's length.
- **`voiceoverDir` may be an absolute `http(s)://` URL** — `VoiceoverTrack`
  then plays the clips from object storage instead of the bundled `public/`,
  which is how per-job audio reaches a worker whose bundle is cached.
- `durations.ts` stays the checked-in default and is still generated, never
  edited; props override it per render, they do not replace it.

What a worker sends: re-voice the manifest lines, ffprobe each clip, then
`--props '{"durations": {…measured…}, "beats": {…if resized…},
"voiceoverDir": "https://…/job-123/vo"}'`. The engine's fits-check still
warns at render time if an overridden line runs past its scene grid.

## Commands

| command | what it does |
|---|---|
| `npm run new-reel -- <id> --name "T" --beats a,b,c` | scaffold template + manifest + scenario + registry entry |
| `npm run voiceover -- scripts/voiceover/<id>.json` | TTS → mp3s → loudness → ffprobe → `durations.ts` |
| `npm run voiceover -- ... --durations-only` | re-measure existing mp3s, no TTS spend |
| `npm run voiceover -- ... --normalize-only` | re-level existing mp3s to -16 LUFS in place (overwrites them) |
| `npm run stills -- <id>-reel [--times 1,5.5] [--frames 30] [--every 2.5]` | one bundle, many stills named by timestamp |
| `npm run render -- <id>-reel --out out/<id>-reel.mp4` | final render |
| `npm run studio` | Remotion Studio |
