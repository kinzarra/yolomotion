# Врезки с ведущим — `dollar-wait` (ВЫПУСК 04)

Talking-head вставки внутрь готового рилса `out/dollar-wait-reel.mp4`
(1080×1920, 30 fps, 105,5 с, `VO_RATE = 1.1`).

---

## 0. Главный принцип: аватар НЕ озвучивает ролик

**Аватар лип-синкается под уже готовые клипы твоего голоса** из
`public/voiceover/dollar-wait/` — режим «Upload audio», не TTS.

Почему это не обсуждается:

- Голос ролика — твой клон ElevenLabs `C5E5SzeWkb4qtqn6iyao`, нормализованный
  в два прохода до −16 LUFS. Голос HeyGen — другой тембр и другой уровень.
- `durations.ts` сгенерирован из этих mp3, а **вся караоке-разметка титров
  в `timeline.ts` считается из этих длительностей**. Переозвучка сдвигает
  каждое слово в титрах и ломает все 12 бит.
- Две дорожки с говорящим голосом пришлось бы дакать друг под друга.

Итог: аудиодорожка ролика **не меняется вообще**. Врезка — это только
видеослой. Тайминг не сдвигается ни на кадр.

---

## 1. Что нужно сделать один раз: аватар

Тип: **Digital Twin (Video Avatar)** — не Photo Avatar. Фото-аватар на
крупном плане в 1080×1920 читается как подделка.

Требования к исходной съёмке (по гайдам HeyGen):

| Параметр | Значение |
|---|---|
| Длина | **2–5 минут одним непрерывным дублем**, без склеек |
| Разрешение | 1080p/30 или выше (4K/60 — лучше) |
| Звук | **обязательно говори вслух** — по нему учится лип-синк |
| Свет | мягкий, равномерный; без жёстких теней и пересветов |
| Фон | однотонный, статичный, простой |
| План | по грудь / поясной, глаза примерно на 1/3 сверху |
| Одежда | без мелкой клетки и полоски (муар), без логотипов |
| Поведение | обычная речь, умеренная жестикуляция, не выходить из кадра |

**Критично: аватар должен быть обучен с матированием (matting)** — иначе
прозрачный фон не отдастся. У свежесозданных Digital Twin / Studio Avatar это
поведение по умолчанию; старые аватары API отклоняет с ошибкой.

Снимай сразу **вертикально**, если основной сценарий — «герой» на весь кадр.

## 2. Настройки генерации

Для компоузинга поверх графики нужен **альфа-канал**, а его даёт только WebM.

| Настройка | Значение | Почему |
|---|---|---|
| `type` | `avatar` | |
| `avatar_id` | твой Digital Twin | `GET /v2/avatars` покажет список |
| **Источник голоса** | **`audio_asset_id`** (загруженный mp3) | НЕ `script` + `voice_id` — см. §0. Поля взаимоисключающие |
| `output_format` | **`webm`** | единственный переключатель прозрачности; mp4 всегда с непрозрачным фоном |
| `background` | **не передавать** | нельзя одновременно убрать фон и задать фон — запрос отклонят |
| `resolution` | `1080p` | 4K избыточно: рилс всё равно 1080 по ширине |
| `aspect_ratio` | `9:16` для «героя», `1:1` для «угла» | у PiP голова должна заполнять круг |
| `engine.type` | `avatar_iv` | дефолтный движок; `avatar_v` — если аватар в него допущен |
| `fit` | не трогать | обрезка делается уже в Remotion |
| `caption` | **не включать** | титры у ролика свои, покадрово синхронные |
| `watermark` | не включать | |
| `voice_settings` | **не трогать** | это настройки TTS; при `audio_asset_id` не применяются |

Если у тарифа нет WebM/матирования — запасной вариант: `output_format: "mp4"`
+ `background: { type: "color", value: "#00B140" }` (хромакей) и кеинг уже на
монтаже. Хуже по краям волос, но рабочий.

## 2a. Экономика (проверено на счёте 2026-08-22)

Биллинг посекундный из USD-кошелька. Для Digital Twin:

| Движок | $/сек | $/мин |
|---|---|---|
| Avatar III | 0,0167 | 1,00 |
| Avatar IV | 0,0667 | 4,00 |

**Выбор движка решает больше, чем количество врезок** — Avatar IV вчетверо
дороже. В кружке Ø 280–620 разница в мимике почти не читается, поэтому серия
идёт на `avatar_iii`.

Фактический прогон: 3 врезки, 8,30 с → списано **$0,15** ($5,00 → $4,85).
Для сравнения, прежние 6 врезок (31,2 с) на Avatar IV стоили бы $2,08.

**Генерировать одним файлом, а не по врезке.** Секунд столько же, но в
документации нигде не сказано, есть ли минимальная тарифицируемая длительность
на видео; если есть — три ролика по 2–3 с выйдут дороже одного на 8 с. Плюс
одинаковый кадр и фон во всех врезках, что и сломалось при ручной сборке.

**Через API нет вотермарки** — она есть только на бесплатном веб-плане.
Перегенерация через API чинит и её, и разнобой фона, заодно.

## 3. Шот-лист

6 врезок, ~31 с лица на 105,5 с ролика (≈25 %). Появления: 7,5 / 13,7 / 40,7 /
54,4 / 69,2 / 85,2 с — не длиннее ~15 с без лица, кроме участка 20–40 с: это
графика курса (85 ₽ → 82,90 ₽) и чек с причинами, там лицо только мешало бы.

Два стиля:

- **ГЕРОЙ** — лицо на весь кадр, графика бита уступает место: остаётся только
  титр внизу и максимум одна плашка. Ставится там, где графика уже отыграла.
- **УГОЛ** — круглый PiP Ø 280 в левом низу, графика идёт целиком. Ставится
  там, где графика — сама суть бита.

Три врезки, 8,30 с генерации — только самые «авторские» фразы, где лицо
работает, а не украшает. Факты, цифры и алгоритм остаются графике.

| # | Врезка | В ролике | Стиль | Клип-источник |
|---|---|---|---|---|
| A | `p1-crowd` | 11,150 → 12,962 | ГЕРОЙ | `02-answer` [5,995–7,988] |
| B | `p2-anxiety` | 54,433 → 56,912 | ГЕРОЙ | `07-mistake` [4,657–7,384] |
| C | `p3-cta` | 100,127 → 103,382 | CTA | `12-cta` [5,420–9,000] |

C заканчивается за 0,4 с до начала петли — стык не трогает.

**Компромисс, о котором надо помнить:** лицо занимает 7 % хронометража, и
между A и B зияет 41 с, между B и C — 43 с без ведущего. Это осознанный
размен ради экономии. Вариант на 5 врезок (14,0 с, $0,23 на Avatar III)
закрывал бы обе дыры: плюс «купил на максимуме — увидел минус» (`04-levels`
[8,806–11,904], в ролике 28,7 с) и «подушку в валюту не переводите`
(`09-who` [7,737–10,542], 69,2 с).

### Текст, который произносит лицо

Это фрагменты уже записанных клипов — **заново ничего писать и начитывать не
надо**. Приведено, чтобы было видно, что именно говорится в кадре.

- **P1** «…Но если после громких новостей вы меняете на доллары все
  сбережения — это классическая ошибка толпы.»
- **P2** «Рубль не просто падает — его лихорадит. В июле он ослаб к доллару
  примерно на пять и восемь десятых процента.»
- **P3** «Но правила „ставка вниз — доллар вверх“ не существует. Рубль могут
  поддержать дорогая нефть…»
- **P4** «Решение принимает не план, а тревога.»
- **P5** «А рублёвую подушку в валюту не переводите.»
- **P6** «Дальше возможны три сценария: ослабление, укрепление — или месяцы
  качелей. Покупка частями…»

Логика выбора: на камере — **оценочные и адресные фразы** (ошибка толпы,
тревога вместо плана, прямой запрет «не переводите»), а факты, цифры и
алгоритм остаются графике. Лицо продаёт мнение, график продаёт цифру.

### Где точки реза

ГЕРОЙ-резы стоят в **измеренных паузах между предложениями** (silencedetect
по mp3), не на глаз:

| Врезка | Пауза в клипе | Резка |
|---|---|---|
| P1 | 1,867–2,008 с в `02-answer` | 1,943 (середина) |
| P4 | 4,584–4,753 с в `07-mistake` | 4,657 |
| P5 | 7,685–7,808 с в `09-who` | 7,737 |

УГОЛ-врезки могут начинаться и кончаться где угодно: **звук под ними не
режется** (это непрерывная дорожка ролика), PiP просто появляется и уходит.

## 4. Геометрия в кадре

**Реализовано в `scenes/Presenter.tsx`** (лежит последним ребёнком `<Reel>`:
выше сцен, ниже титров, под общим grade/grain/vignette — поэтому врезка
попадает в ту же цветокоррекцию, что и графика).

Исходник горизонтальный 1280×720 без альфы. **Оба вида — круги**, отличаются
только размером и наличием подложки:

- **ГЕРОЙ** — круг Ø 620 по центру, `top = 600`, кольцо 5 px. Под ним матовая
  подложка на всю ширину, `y 570–1225`.
- **УГОЛ** — круг Ø 280 на `(110, 1105)`, кольцо 4 px, без подложки: графика
  идёт целиком.

**Кадрирование лица.** Квадрат 500×500 от `(385, 6)`, отмеренный по сетке
128×72 на реальных кадрах. Лицо в исходнике **не по центру**: его центр
≈ `x 635`, глаза ≈ `y 196` — левее и выше середины кадра. Симметричный кроп
уводил бы голову вбок, а половину круга занимала бы стойка микрофона. Квадрат
посажен так, чтобы **глаза оказались на 38 % высоты круга** — ровно по центру
лицо выглядит «утонувшим».

**Края подложки.** По вертикали — жёсткие, потому что зазор 11 px: низ
заголовка ≈565 (обязан выжить, это мысль бита) и верх чека 576 (обязан
исчезнуть). Градиент в 11 px не помещается — первая версия попробовала и
съела вторые строки заголовков. Нижняя граница 1225 проходит между плашкой
`answer` (1150–1210, гасится) и плашкой `who` (с 1230, остаётся — она несёт
инструкцию); плашка `mistake` с 1272 тоже цела.

По горизонтали — мягкие (9 % с каждой стороны). Круг уже карточки, и жёсткие
края оставляли бы по бокам плоские полосы мёртвого фона. Вся графика сцен
живёт между `x 90` и `x 990`, поэтому растушёвка по краям ничего не открывает,
но сохраняет живое лаймовое свечение у границ кадра.

Подложка появляется **втрое быстрее круга** — иначе первые кадры входа чек
просвечивает сквозь полупрозрачный круг и это читается как двойная экспозиция.

Оба вида: `<OffthreadVideo muted playbackRate={VO_RATE}>`. Длина в кадрах
берётся из `presenter.ts` как `duration / VO_RATE * fps`.

**Отключение врезки.** `"enabled": false` в манифесте — шот всё равно
нарезается (офсеты `--slice-concat` считаются как нарастающая сумма длин, и
удаление шота сломало бы масштабный коэффициент), но не рендерится. Сейчас так
отключён `p6-scenarios`: в текущем экспорте фон удалён только на этой сцене, и
белый кружок среди студийных выбивался.

## 4a. Геометрия под вертикальный исходник (если будет)

**ГЕРОЙ** — WebM 9:16 на весь кадр, фон прозрачный, под ним остаётся фон
сцены (`SceneShell`: пиксельная сетка, лаймовое свечение, сканлайны).
Сверху — только титр на `y = 1416` и, если нужно, одна плашка. Бренд-бар
`ДЕНЬГИ · ПРОСТО / ВЫПУСК 04` остаётся всегда.

**УГОЛ** — круг **Ø 280 px, левый верхний угол бокса (110, 1105)**, лаймовое
кольцо 4 px, мягкая тень. Зона проверена на реальных кадрах: свободна во всех
трёх битах, где стоит PiP (под графиком лихорадки, в пустой полосе «второй
стороны», под дорожками сценариев). До титров на `y = 1416` остаётся 31 px —
запас небольшой, поэтому кольцо не толще 4 px.

## 5. Как генерировать

**Основной путь — одна команда от начала до конца:**

```bash
npm run heygen -- scripts/presenter/dollar-wait.json --generate --dry-run  # смета, без трат
npm run heygen -- scripts/presenter/dollar-wait.json --generate            # и поехали
```

Режет слайсы из house-клипов → склеивает в один mp3 → грузит в `/v3/assets` →
генерирует одно видео → ждёт → скачивает в `out/heygen/` → режет обратно на
врезки → пишет `presenter.ts`. Смета печатается до траты.

Остальные режимы (ниже) — для случаев, когда генерация делается руками в
интерфейсе.

## 5a. Ручные маршруты

**На free-плане работает только маршрут Б:** одно видео там ограничено
1 минутой, а мастер — 107,7 с, HeyGen его отклоняет
(«Your video is longer than 1min»). Маршрут А держим на случай апгрейда.

### Б. По одной врезке — рабочий

Генерится ровно то, что окажется в кадре: шесть файлов по 2,7–7,0 с, каждый
заведомо короче минуты. Слайсы уже нарезаны в `out/presenter-slices/`.

Экспорты из интерфейса нужно назвать по id врезки (`p1-answer.webm` …),
сложить в `public/presenter/dollar-wait/` и подобрать:

```bash
npm run heygen -- scripts/presenter/dollar-wait.json --adopt
```

Он измерит каждый файл, сверит с длиной аудио, из которого тот сделан
(расхождение >0,15 с = лип-синк поедет), и запишет `presenter.ts`.

Пересобрать слайсы после правки `from`/`to` в манифесте:
`npm run heygen -- scripts/presenter/dollar-wait.json --master` не нужен —
достаточно перерезать mp3 тем же ffmpeg-ом, что и в §3.

### А. Мастер целиком, нарезка потом — при платном плане

Одна генерация на весь ролик, врезки вырезаются уже из неё.

```bash
npm run heygen -- scripts/presenter/dollar-wait.json --master
# → out/presenter-slices/dollar-wait-master.mp3  (107,74 с, все 12 клипов встык)
# → out/presenter-slices/dollar-wait-master.json (офсет каждого клипа)

# после того как HeyGen вернул видео:
npm run heygen -- scripts/presenter/dollar-wait.json --slice <master-video>
```

Плюсы: один заход в интерфейсе вместо шести, и **точки врезок можно двигать
без перегенерации** — правишь `from`/`to` в манифесте и режешь заново.
Минус: к оплате 107,7 с вместо 31,2 с.

Клипы кладутся встык через `adelay` + `amix`, а не через concat-демультиплексор:
mp3 даёт задержку кодировщика на каждом стыке, и двенадцать стыков накопили бы
дрейф, слышимый против дорожки ролика. Позиция врезки в мастере =
`офсет[клип] + from`; всё считается из измеренных длительностей.

Аспект у мастера один — берём **9:16**, а для «угловых» врезок квадрат под PiP
вырезается из кадра при компоузинге.

### Б. По одной врезке — если нужно только доснять кусок



`.env` в корне репозитория:

```
HEYGEN_API_KEY=...
HEYGEN_AVATAR_ID=...
```

```bash
# посмотреть, что уйдёт в API, без единого потраченного кредита
npm run heygen -- scripts/presenter/dollar-wait.json --dry-run

# сгенерировать всё
npm run heygen -- scripts/presenter/dollar-wait.json

# перегенерировать одну врезку
npm run heygen -- scripts/presenter/dollar-wait.json --only p4-mistake
```

Скрипт: нарежет слайс из mp3 (ffmpeg, с перекодировкой — stream copy
округляет до границы mp3-фрейма и увёл бы лип-синк на 26 мс) → загрузит его в
`POST /v3/assets` → создаст видео `POST /v3/videos` → дождётся `completed` →
скачает WebM в `public/presenter/dollar-wait/` → измерит длительности и
запишет `src/templates/dollar-wait/presenter.ts`.

Тот же принцип, что с `durations.ts`: **измеренные числа не набираются
руками**. Если длина готового видео разойдётся с длиной его аудио больше чем
на 0,15 с, скрипт предупредит — это значит, что лип-синк уедет.

Список аватаров:

```bash
curl -H "X-Api-Key: $HEYGEN_API_KEY" https://api.heygen.com/v2/avatars
```

## 6. Сборка обратно в ролик

WebM ложится в сцену как `<OffthreadVideo>` (не `<Video>`) с:

- `muted` — звук уже идёт из `VoiceoverTrack`;
- `playbackRate={VO_RATE}` (1.1) — ровно как у голосовой дорожки, иначе губы
  разъедутся с речью примерно на 10 %;
- стартом на `reelIn`, длиной `(to − from) / VO_RATE`.

Всё это уже лежит в сгенерированном `presenter.ts`.

Один нюанс с петлёй: в CTA (95–105,5 с) врезок нет намеренно — последний кадр
ролика должен совпадать с нулевым (кнопка «КУПИТЬ» + курсор), а лицо в этом
кадре сделало бы стык видимым.

## 7. Если что-то пошло не так

| Симптом | Причина |
|---|---|
| Видео с чёрным/белым фоном | не передан `output_format: "webm"` — по умолчанию mp4 непрозрачный |
| API отклоняет запрос на прозрачность | аватар обучен без матирования → пересоздать Digital Twin |
| Ошибка «script and audio are mutually exclusive» | в теле остались и `script`, и `audio_asset_id` |
| Губы отстают/спешат по всему ролику | забыт `playbackRate = 1.1` на `OffthreadVideo` |
| Губы уезжают к концу одной врезки | длина WebM ≠ длине слайса — скрипт про это предупреждает |
| Аватар «дышит» в тишине дольше клипа | HeyGen добавил хвост — обрезать по `duration` из `presenter.ts` |

## 8. Проверено / не проверено

**Проверено:** схема API v3 (`/v3/assets`, `/v3/videos`) по актуальной
документации HeyGen на август 2026; `--dry-run` на всех шести врезках;
границы слайсов (каждый начинается с паузы 0,06–0,10 с, то есть рез попадает
на начало фразы, а не в середину слова); зона PiP — на реальных кадрах ролика.

**Не проверено:** живая генерация — нет ключа, и тратить твои кредиты без
спроса я не стал. Первым делом прогони `--only p4-mistake` (2,7 с, самая
дешёвая врезка) и посмотри на результат, прежде чем запускать все шесть.
