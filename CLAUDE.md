# Yolomotion — programmatic video platform (Remotion)

npm-workspaces monorepo. `packages/video` is the Remotion project,
`packages/renderer` renders programmatically (future SaaS render worker).
See README.md for the full architecture and the SaaS roadmap.

## Rules

- A scenario/script/brief for a new video → read
  `.claude/skills/reel-production/SKILL.md` FIRST. It is the pipeline:
  scenario file → `new-reel` → voiceover → (face → footage) → timeline →
  scenes → stills → render. Do not hand-roll a template.
- **Footage is evidence, not wallpaper.** Photos, screenshots and clips enter
  a reel only as an `улика:` line under a beat in the scenario, graded into
  the palette, inside one of three containers (paper / screen / studio) —
  `.claude/skills/reel-production/references/footage.md`. Never add B-roll
  to a finished reel to make it "less graphic".
- **Anything that costs money (HeyGen seconds, AI video) is quoted from a
  dry run and confirmed by the user before it is generated.** Say what the
  wallet did afterwards.
- ALWAYS read `.claude/skills/remotion-motion-graphics/SKILL.md` before writing
  any Remotion/animation code, and follow its 10 rules and verification loop
  (render → extract frames → inspect → fix → re-render).
- Voiceover reels are built on the engine in `packages/video/src/reel/`
  (`Reel`, `Scene`, `buildScenes`, `defineVoiceover`, shared `Captions`).
  Never copy a caption engine or a voiceover track into a template again.
- Clip durations live in the generated `templates/<id>/durations.ts`. Never
  type a measured duration by hand; never edit that file.
- Colors, easings, springs come ONLY from `packages/video/src/theme.ts`. Never
  inline them in components.
- A video template = folder in `packages/video/src/templates/<id>/` with a zod
  `schema.ts`, a component, and `defineTemplate({...})`; register it in
  `templates/index.ts`. Composition ids are `<template>-<format>`.
- Brand parameterization goes through input props (zod schema), not through
  editing the template.

## Commands (run from repo root)

- `npm run studio` — Remotion Studio
- `npm run new-reel -- <id> --name "Title" --beats a,b,c` — scaffold a reel
  (template wired to the engine + voiceover manifest + scenario stub +
  registry entry)
- `npm run render -- <compositionId> [--props file.json] [--out file.mp4]`
- `npm run stills -- <compositionId> [--times 1,5.5] [--every 2.5]` — the
  verification loop: one bundle, many stills named by timestamp
- `npm run sfx` — synthesize SFX/music WAVs into `packages/video/public/sfx/`
- `npm run voiceover -- scripts/voiceover/<id>.json` — ElevenLabs TTS from a
  manifest (voice id + lines) into `public/voiceover/<id>/`, normalized to
  -16 LUFS, then ffprobe → generated `templates/<id>/durations.ts`. Add
  `--durations-only` to re-measure existing mp3s without spending TTS credits.
  Needs `ELEVENLABS_API_KEY` in the repo-root `.env`.
- `npm run heygen -- scripts/presenter/<id>.json [--dry-run] [--only <shot>]` —
  talking-head inserts. The avatar **lip-syncs to slices of the existing
  voiceover mp3s** (`audio_asset_id`), never HeyGen TTS: re-voicing would
  invalidate `durations.ts` and every caption timing derived from it. Outputs
  alpha WebM (`output_format: "webm"` is the only transparency switch, and it
  is mutually exclusive with `background`) into `public/presenter/<id>/`, plus
  a generated `templates/<id>/presenter.ts`. Only the seconds actually on
  screen are uploaded. Needs `HEYGEN_API_KEY` + `HEYGEN_AVATAR_ID` in `.env`.
  Composite with `<OffthreadVideo muted playbackRate={VO_RATE}>`.
  `--generate` does the whole thing: slices → one concatenated mp3 → one API
  call → download → re-slice → `presenter.ts`. Add `--dry-run` for the cost
  estimate first. Generate as ONE file, never per shot: the seconds are
  identical but the docs never state whether a video has a minimum billed
  duration. API output has no watermark (that is a free web-plan limit).
  `--slice-concat <video>` / `--adopt` handle footage generated by hand in the
  UI instead.
  **Which character, and what it costs.** The manifest's `avatarId` may name an
  env var — `"${HEYGEN_AVATAR_VIEW_ID}"` — and that named variable is what gets
  resolved; a bare id is used as-is, and neither falls back to
  `HEYGEN_AVATAR_ID`. The account holds a Digital Twin (`511aa716…`, «Philipp»)
  plus five generated **photo-avatar looks** in the same group (`1b80626e…`),
  one of which is the podcast-studio shot `HEYGEN_AVATAR_VIEW_ID`. List them:
  `curl -H "X-Api-Key: $HEYGEN_API_KEY" https://api.heygen.com/v2/avatar_group/1b80626e44c945edbad8f5024ce9163b/avatars`.
  A photo avatar is billed on a **different table** from a twin, and the two

## Notes

- `main.py` is a leftover PyCharm scaffold, unrelated to the platform.
- Loudness normalization in `gen-voiceover.mjs` is deliberately two-pass
  (`linear=true`). Single-pass loudnorm rides the gain and lifts the cloned
  voice's noise floor ~10 dB in the pauses — it is audible as hiss.
- `scripts/voiceover/yoloco-audience-fit.json` still carries the wrong voice id.
- `database-guide`'s clips were synthesised before the loudness pass existed
  and sat ~9 dB below every other reel; they were re-levelled in place with
  `--normalize-only` on 2026-08-20 and the compensating `voVolume` gain was
  removed. Its closing scene was also 0.3s too short, which cut the last word
  off in the encode — the reel is 28.5s now, not 28.
- `--out` on `npm run render` / `npm run stills` resolves relative paths
  against the repo root, not the renderer package. Absolute paths work too.
- Rendered files go to `out/` (gitignored).
- **Real people in reels**: photos come from Wikimedia Commons under CC BY,
  are listed in `public/images/CREDITS.md`, graded to greyscale at render
  time, and the closing beat carries the credit line. Cut a subject onto
  transparency with `scripts/matte.swift` (macOS Vision framework:
  `swiftc -O scripts/matte.swift -o /tmp/matte && /tmp/matte in.jpg out.png`)
  — it handles dark-on-dark, which the flood-fill `scripts/cutout.mjs` cannot.
  `khaby-silence` is the reference: four mattes, one credit line, no likeness
  ever synthesised.
- `khaby-silence` is the premium editorial look (black / bone / one flat
  vermilion, serif-italic accent word via `theme.fonts.serif`, white caption
  highlight with `+WORD` keywords in the accent). Reuse its `ui.tsx` for the
  next piece in that register rather than inventing a new kit.
- **Russian-language reels**: Space Grotesk (`theme.fonts.display`) has no
  Cyrillic. Use `theme.fonts.wide` (Unbounded, 500–900, Cyrillic subsets) for
  heroes and pass `captions={{ fontFamily: theme.fonts.wide }}` to `<Reel>`.
  Unbounded has no `₽` glyph — stack `theme.fonts.mono` behind it
  (`digital-ruble`'s `Kinetic` does). Caption word weights are Unicode-aware,
  so Cyrillic karaoke timing is correct.
- `digital-ruble` is the «ЧЕК × ПИКСЕЛЬ» personal-finance-blog style (thermal
  receipts + acid-lime glitch); reuse its `ui.tsx` kit for the next episode
  of that series rather than inventing a new look.
  `btc-squeeze` (ВЫПУСК 02), `phone-check` (ВЫПУСК 03), `dollar-wait`
  (ВЫПУСК 04) and `no-it-in-russia` (ВЫПУСК 05) are the reference for how:
  their `palette.ts` re-exports the `digital-ruble` palette, their `ui.tsx`
  does `export * from "../digital-ruble/ui"` (or from the previous episode) and
  adds only episode-specific primitives. Next episode = same pattern,
  `episode: "ВЫПУСК 06"`.
  `no-it-in-russia` is also the reference for a **face-led hook**: the
  presenter is composited inside `HookScene` rather than in a `<Presenter>`
  layer over every scene, because the studio footage is that beat's background
  and the headline has to sit on top of it. It drops the brand bar for that one
  beat (the bar's rule at y≈180 collides with the hair at y≈171) and does not
  loop — a graphics CTA cannot match a frame-0 face without paying for a second
  avatar insert.
  `phone-check` and `dollar-wait` also show how to loop a reel: the last CTA
  frame matches hook frame 0 through `scenes/shared.ts`, the final scene runs
  `exit={false}`, and everything visible at hook frame 0 enters with
  `delay={-40}` — including anything small like a corner label, or it pops on
  the wrap. A third signal color is never added — the series maps
  "blue = law" to thermal paper, "green = protection" to lime, and in
  `dollar-wait` the dollar is paper too rather than dollar-green.
- Long-form briefs (a 10-minute YouTube script) become a **vertical
  cut-down**: keep every block's point and its ТЕКСТ НА ЭКРАНЕ, drop the
  supporting sentences, and size the beats from the measured clips.
  `dollar-wait` is the reference — 8 script blocks → 12 beats → 105.5s.
  Say so in the scenario's *Deviations* section.
- Unbounded (`theme.fonts.wide`) has no `≠`, `₽`, `−` or `↑↓`. Stack
  `theme.fonts.mono` behind it, or make the glyph a deliberate element in
  the mono face (see `dollar-wait`'s `CounterScene`) rather than letting one
  character silently fall back mid-headline.
- **Unbounded is much wider than it looks.** Budget ~0.78em per Cyrillic
  capital: a 12-character word at `size: 92` overruns the 900px column, and a
  free-standing `—` counts as a whole word in `Kinetic` and pushes the next one
  onto its own line. Every headline overflow in `no-it-in-russia` was one of
  those two. Set the size, then look at a still — do not estimate.
- **Never wrap an opaque layer in `<Glitch>`.** It composites two channel
  copies in `screen` blend mode, so a near-black scrim screened onto itself
  twice lifts the whole frame to mid-grey. Glitch the footage and the type
  separately and leave the scrims between them alone (`HookScene`).
- `useIn` / `useRamp` read the frame, so they are hooks: they cannot be called
  inside a `.map()` body or behind a `?:`. Primitives that need one ramp per
  item (`FallingBars`, `Stairs`, `TaskCard`) read `useCurrentFrame()` once and
  use a plain eased `interpolate` helper instead.
